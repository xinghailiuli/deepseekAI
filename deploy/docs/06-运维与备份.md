# 06 · 运维与备份

## 一、守护：别指望它不挂

三件事每天都会发生：DSH 重启、容器停、Node 进程被 OOM 干掉。
所以用 Windows 计划任务 + 脚本兜底，**不要**装成系统服务（session 0 抓不到桌面、点不了鼠标）。

### 两个计划任务

| 任务名 | 频率 | 干什么 |
| --- | --- | --- |
| `QQWhale-Guard` | 每 3 分钟 | 巡检 3100/3200/3205/13000，掉哪个拉哪个 |
| `QQWhale-Watchdog` | 开机 + 登录 | 一次性把所有服务拉起来 |

注册（**必须 Highest 权限**，否则点不动别的窗口）：

```powershell
schtasks /Create /TN "QQWhale-Guard" /TR "wscript.exe \"D:\...\run-hidden.vbs\"" `
  /SC MINUTE /MO 3 /RL HIGHEST /F
```

`run-hidden.vbs` 的作用：**不弹黑窗口**。用户明确要求过「别老是闪窗」。

### 巡检脚本要探端口，不是探进程名

进程在但端口没起（比如桥接连不上 SnowLuma 自己退出）也是坏的。
`Test-NetConnection 127.0.0.1 -Port 3100` 才是真的活着。

## 二、日志

```
qq-bridge/state/bridge.log         超过 5MB 自动轮转 .1
qq-bridge/state/tool-calls.jsonl   一次工具调用一行（含 args / 结果 / 耗时）
features/小黑盒/audit.jsonl         发帖/评论审计
```

排查顺序：**先看 tool-calls（它到底做了什么）再看 bridge.log（桥接怎么处理的）**。
光看日志容易被「接口返回 ok」骗。

常用：

```powershell
# 它最近调了哪些工具
Get-Content state\tool-calls.jsonl -Tail 40 | % { $_ | ConvertFrom-Json } |
  Where-Object type -eq 'call' | Select-Object time,tool -Last 10

# 有没有卡在结算页/弹窗
Select-String state\bridge.log -Pattern '会话繁忙|暂存唤醒'

# 它今天说了什么
curl "http://127.0.0.1:3100/api/socialV2/recent?key=private:<号>&limit=20" -H "x-console-token: $ct"
```

## 三、备份到 GitHub

`鲸鱼档案/` 是个独立 git 仓库，只放「不会泄露隐私」的东西：

```
人物卡/   人设快照（带日期）
日记/     每天一篇
喜好/     喜好与习惯
.gitignore  ← 聊天记录/ 必须排除
```

```powershell
cd 鲸鱼档案
powershell -File backup.ps1        # 自动加时间戳提交并 push
```

### 三个红线

1. **聊天记录不入库**（`.gitignore` 里锁死，别手滑 `git add -f`）
2. **任何 token / cookie / 密码不入库**；`config.json` 用模板，真配置进 `.gitignore`
3. 仓库是 public 的话，人设里不要写真实姓名、住址、手机号

## 四、密钥轮换

部署跑通后建议做一次：

- [ ] GitHub PAT 只在需要时贴，用完清空 `config.json` 的 token 字段
- [ ] noVNC 密码换掉（默认密码等于把容器桌面挂公网）
- [ ] `state/console-token` 定期重生成（等于管理员密码）
- [ ] 检查 DeepSeek 侧用量，防止 key 被反复白跑

## 五、升级顺序

```
停看门狗 → 停桥接 → 备份 config/state → 更新代码 → 启桥接 → 验三项（connected/online/dshReady）
→ 启看门狗 → 让它自己跑 10 分钟看 audit
```

**永远先备份 config.json 和 state/**，那是唯一不能重建的东西。

## 六、给它换个人格

角色卡是纯 Markdown（`qq-bridge/roles/<名字>.md`），改完即生效（下次唤醒重读）。
建议控制在 **3,000 字以内**：每轮都要重读一遍，写太长会明显变慢。

四条必须写进去：

1. 怎么说话（长度、分段、不换行）
2. 它有哪些工具、什么时候用（工具名写死，别写「你可以查资料」）
3. 绝对不能做的事（列清单）
4. 游戏/发帖这类「操作型」任务的顺序（先点按钮再汇报，别反过来）
